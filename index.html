Linuxi alused

Linuxi failisüsteem
algab juurkaustast /

Linuxis paiknevad failid ja kaustad ühe puu kujul. Selle algus on juurkataloog /. Sealt hargnevad kasutajate failid, süsteemi seadistused, programmid ja muutuvad andmed eri kaustadesse.

Absoluutne failitee näitab asukohta alates juurkataloogist, näiteks /var/log. Kataloog /root on administraatori kodukaust ja erineb juurkataloogist /.

Kui ühendad Linuxi sülearvutiga USB-mälupulga, ei muutu see Windowsi moodi E: kettaks. Selle sisu avaneb olemasoleva failipuu kaustas, näiteks /media/usb-stick. Ka serveri lisaketas ühendatakse mõne kausta külge, näiteks /mnt/andmed. Sellist kausta nimetatakse ühenduspunktiks; täpne tee sõltub süsteemi seadistusest.

01 / Linuxi failisüsteem

Üks juur, palju kaustu

Kõik absoluutsed failiteed algavad samast / juurkataloogist. Allolev skeem näitab 16 levinud kausta; vali kaust, et liikuda selle selgituse juurde. Sinu süsteemis võib kaustade valik erineda.

01
Linuxi server ja töölaud

Paljud serverid töötavad graafilise töölaua ja failihaldurita. Linuxi töölauaarvutil võivad mõlemad olemas olla. Windowsi kettatähtede asemel asuvad ka ühendatud andmekandjad ühe / juurest algava failipuu all.

Ühendatud andmekandjad

Ketas saab failipuus asukoha

Kui andmekandja ühendatakse, muutub selle sisu kättesaadavaks valitud kausta kaudu. Seda nimetatakse ühendamiseks (mounting) ja kausta ühenduspunktiks.

USB-mälupulk
/→media→usb-stick
Serveri lisaketas
/→mnt→data

Näidisteed on /media/usb-stick ja /mnt/data. Ühenduspunkti nimi ning asukoht võivad erineda.

Üks kasutaja on erand

Ülemkasutaja root kodukaust

Ülemkasutaja root kodukaust on tavaliselt /root, mitte /home/root. See paikneb juurkataloogi / all samal tasemel kui /home. Sõna „root“ tähistab siin kasutajakontot; üksik / tähistab kogu failipuu algust.

02

Käsk ja failitee

Mida terminalis kirjutatud tee tähendab?

Käsk on terminalis antud juhis. Näites ls /var/log on ls programmi nimi ja /var/log kaust, mille sisu küsitakse. Kui sisestad välise programmi nime ilma kaldkriipsuta, otsib käsukest seda oma PATH loendis olevatest kaustadest. Mõned käsud, näiteks Bashi pwd, võivad olla kesta sisse ehitatud.

Kirjutadls /var/log
→
Programmi näidistee/bin/ls

Sihtkaust/var/log

/bin/ls ja /bin/cp on võimalikud programmitäisteed. Mõnes süsteemis asuvad programmid tegelikult /usr/bin all ning /bin on sinna viitav link. Kontrolli oma masinas käsuga type -a ls.

Näidisjuhtum · veebileht

Veebileht vastab „404 Not Found“

Näidispildil annab nginx HTTP vastuse 404: küsitud ressurssi ei leitud. Vastus näitab, et päringule vastati, kuid üksi ei ütle, kas viga on aadressis, veebiserveri seadistuses või rakenduse marsruudis.

shop.example.com404Not Found · näidis
Samm ja käskMida kontrollib?Kuidas teed lugeda?
1. curl -i --max-time 10 https://shop.example.com/Teeb GET-päringu ning kuvab HTTP päised ja vastuse; --max-time 10 piirab kogu toimingu kümne sekundiga.https://shop.example.com/ on veebiaadress. Lõpus olev / on URL-i tee, mitte Linuxi juurkataloog.
2. systemctl status nginx --no-pagerNäitab, kas nginx-i teenus töötab; oleku vaatamine ei taaskäivita seda.nginx on teenuse nimi, siin pole failiteed.
3. nginx -TKontrollib seadistust ja väljastab selle. Otsi sobiva saidi server_name, location ja root määrangud.Seadistuses olev root võib määrata kohaliku failikausta; käsk võib vajada õigusi ja väljundit ei tasu avalikult jagada.
4. ls -lah /var/www/htmlVaatab faile näidiskaustas, kui seadistus suunab saidi just sinna./var/www/html on Linuxi failitee. Tegelik veebikaust võib olla mujal või vastuse võib koostada rakendus.

Aadress shop.example.com, vastus ja failitee on väljamõeldud näited. 404 ei tõesta ühte kindlat juurpõhjust.

Allikad: HTTP 404 tähendus ja nginx-i käsureavalikud.

Võrgutõrke kontrollkäik Linuxis

Näidispakiautomaadil on 192.168.10.24/24 ja lüüs 192.168.10.1. Kontrolli kihte selles järjekorras; väärtused tuleb päris seadme järgi asendada.

  1. ip -br addressKas IP ja prefiks on liidesel olemas?
  2. ip routeKas vaikemarsruut osutab oodatud lüüsile?
  3. ip route get 1.1.1.1Milline liides ja lähteaadress valitaks?
  4. ping -c 4 192.168.10.1Kas kohalik lüüs vastab ICMP-le?
  5. resolvectl query example.comKas DNS saab nime lahendada?
  6. curl -I --connect-timeout 5 https://example.com/Kas HTTPS ühendus ja esmane vastus toimivad?
